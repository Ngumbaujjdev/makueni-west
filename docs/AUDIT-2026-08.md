A point-in-time record of what's actually built vs. stubbed, verified by reading the code directly (not inferred from folder names or old scope docs). Written so this doesn't have to be re-derived in a future session — if something below turns out to be stale, trust the current code over this file and update it.

## Backend (`backend/`, Laravel 12)

### Done — fully built (migrations + models + controllers + routes)

| Module | Notes |
|---|---|
| **Auth** | Sanctum-based login, `login-code` (employee-code + PIN alt login), `logout`, role-switching, password reset (self-service token, admin-assisted, employee-code flows), profile updates, full audit trail (`/auth/user/{id}/audits*` for login/password/profile/status history). Most mature module. |
| **Roles & Permissions** | Spatie-backed, extended with a `Module → ModuleGroup → Submodule → SubSubmodule → Permission` hierarchy. Full CRUD + dedicated role-permission-assignment endpoints. See `backend/docs/api-changes/` for the changelog of this area — it's been iterated on the most. |
| **Territory hierarchy** | Single Table Inheritance on one `territories` table — `Diocese`, `Region`, `Subregion`, `Church` models. Type-specific controllers (`DioceseController` 384 lines, `RegionController` 318 lines, `ChurchController` 280 lines) + generic `TerritoryController` for hierarchy/tree queries. `UserTerritoryAssignment` for user-to-territory scoping, with its own audit trail. |
| **Budgets** | The largest, most recently built subsystem (migrations dated Jan 2026). `budget_types → budget_categories → budget_lines → budgets → budget_line_items`, full workflow (submit/approve/reject/activate/close/clone), deductions (apply/reverse/recalculate), logs/audit trail, fiscal periods (`fiscal_years`/`quarters`/`semi_annuals`/`months`), Excel export, financial summaries. |
| **Support tickets** | Full lifecycle: create (public), assign, notes, resolve, close, activity/status history. |

### Testing & Code Quality

Standard PHPUnit (not Pest). `phpunit.xml` pre-declares 5 suites: `Unit`, `Feature`, `Diocese`, `Financial`, `Demographics`. Only the default `tests/Feature/ExampleTest.php` and `tests/Unit/ExampleTest.php` exist — **zero real test coverage today**, across every module including the mature ones (Auth, Permissions, Territory, Budgets). `composer.json` already defines a `composer test` script (config-clear + `artisan test`) and a `composer dev` script (`npx concurrently`: server + queue listener + `pail` logs + `npm run dev`) — the latter mirrors `compass`'s dev-orchestration pattern almost exactly.

`laravel/pint` (code style) and `nunomaduro/larastan` (PHPStan-based static analysis) are both already in `require-dev` — easy to miss on a quick composer.json read, confirmed by reading the full file. Pint has no `pint.json` (runs Laravel's default preset). Larastan has **no `phpstan.neon`** — installed but not yet runnable out of the box.

The `npm run dev`/Vite/Tailwind scaffold inside `backend/` (`backend/package.json`, `resources/js/{app,bootstrap}.js`, `resources/css/app.css`) is Laravel's untouched default install boilerplate — never wired to anything real. The actual frontend is the separate PHP/YNEX app at the repo root; don't confuse the two.

## Seeders (`backend/database/seeders/`)

Real and rich — 5 real Regional Overseers and 13 real named Pastors, not generic placeholders, seeded via `DioceseLeadershipSeeder.php` and `RegionalLeadershipSeeder.php`. Two concrete bugs found (not yet fixed — see `ROADMAP.md`):

1. **Bishop email collision**: `SampleUsersSeeder` (Phase 2 of `DatabaseSeeder`) and `DioceseLeadershipSeeder` (Phase 6) both `User::firstOrCreate(['email' => 'bishop@makueniwestdiocese.or.ke'], ...)` with different data (David Mutua / PIN 2468 vs. Peter Kilonzo / PIN 1234). `SampleUsersSeeder` runs first, so its record wins today — the login currently resolves to "David Mutua," not the intended "Peter Kilonzo."
2. **Non-deterministic PINs**: `SampleUsersSeeder`'s generic Regional Overseers and Pastors get `Hash::make(str_pad(rand(1000, 9999), ...))` — a random PIN that's unrecoverable after seeding. Password (`password`, fixed) still works for these accounts.
3. **Coverage gaps**: no seeder creates a Subregional Overseer user (role exists, unused) or users for Diocese Secretary/Treasurer/Administrator (roles exist, unused).
4. `SampleUsersSeeder`'s generic users (`Regional Overseer <region name>`, `Pastor Sample <n>`) appear to be superseded scaffolding from an earlier iteration — `DioceseLeadershipSeeder` + `RegionalLeadershipSeeder` create the same *kinds* of users but with real names, phone numbers, and spouse data.

See `TEST-LOGINS.md` for the actual credentials this produces today.

## Multi-tenancy readiness (addendum, later same day — confirmed as a real requirement, not just a hypothetical)

`App\Enums\TerritoryType` (`backend/app/Enums/TerritoryType.php`) already defines a `GLOBAL` level *above* `DIOCESE`: `GLOBAL(0) → DIOCESE(1) → REGION(2) → SUBREGION(3) → CHURCH(4)`, with `GLOBAL.canHaveChildren() === true`. `App\Http\Controllers\Api\TerritoryController::index()` has working logic and an explicit comment — "Global admin sees ALL dioceses (root level)" — that only makes sense if multiple Diocese-type root territories were anticipated. `grep -rn "CCI-MWD" app/ routes/` (outside `database/seeders/`) returns nothing — no controller or route hardcodes the one diocese that currently has data. In short: the schema and at least `TerritoryController` were built with multi-diocese in mind, even though only one diocese has ever been seeded and no login/onboarding flow for a second diocese exists yet. See `ROADMAP.md` → Multi-Tenancy Readiness for what's still unverified (data isolation across other controllers, diocese-code login, tenant onboarding).

## Original scope docs (`makueni west diocese documents/`, mid-2025 to Nov 2025)

Originally specified Vue.js as the frontend framework — not what was actually built (the PHP-include + fetch hybrid described above); this is noted for history only, not acted on (see decision in `ROADMAP.md` / root `CLAUDE.md`: keep the current stack).
